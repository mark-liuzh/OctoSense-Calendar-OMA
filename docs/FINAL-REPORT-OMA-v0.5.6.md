## 三、失败原因分析

### 3.1 直接死因

- **性能 4 分** —— 五项中最低。评委在官方 rc.6 宿主上跑应用，写入按钮根本点不出来，AI 排程 2 秒就因为 schema 用了宿主不支持的 `pattern` 而失败。
- **完整度 10 分** —— 写入主线在评委手里走不通；月视图刷新超出宿主指令预算；冲突导入走不到改期；邮件导入报 "no such account"。
- **技术贡献 6 分** —— 没往 Rinx / OctoSense / makepad 上游提过 PR。
- **结果**：总分 48，距三等奖线（70）差 22 分，距一等奖（80）差 32 分。

### 3.2 深层原因

#### A. 我们在 Windows 测，评委在 macOS rc.6 测 —— **两套宿主**之间有差异

- 我们的 card-host 编译出来跟官方 rc.6 的指令预算、支持的 `pattern` 子集不一致。
- v0.5.5 / v0.5.6 的核心改动（AI 排程、待办转日程、事件详情、历史回滚、取消重排）全部依赖 `model.complete` 服务，而 v0.5.5 上线时 Ody 已确认**当前 card-host / Shell 都没有 `model` 服务**——我们在本机测的只是降级路径。
- 我们的全量回归测的是 v0.5.6 的"功能可达性"（功能能跑、UI 不崩），**但没在官方 rc.6 上做过 e2e 验收**。这正是评委扣性能分的关键。

#### B. 答辩主线没有把"数据安全/可回滚"讲成唯一亮点

- 我们做了**七道闸校验 + 用户确认 + 冲突未减就自动回滚**这个很扎实的工程化闭环，**创意分 13**（中上）就是评委认这个。
- 但**实用性 15** 已经是 OMA 的最高分了——说明评委相信"日历冲突"是真问题、导入 ICS 是好入口。
- **但 v0.5.5 真正吸引人的"AI 排程"在评委手里跑不起来**。故事的卖点被自己写出来的新功能反噬。

#### C. 上游贡献 = 0

- Rinx / OctoSense / makepad / App Hub 仓库里，**OMA 一个 PR 都没提**。
- 其他强队（牵线 72 分、OctoBuddy 67 分、DailyFlow 67 分）都有上游 PR 并被评委折算到技术分。
- 这一项技术上我们至少能拿 8-10 分（"复现与工程 8/10 折算"），但折算后只有 6 分。
- **如果能提哪怕 1-2 个 Rinx/OctoSense 修复 PR，技术分就可能从 6 提到 12+。**

#### D. 复赛答辩没把"为什么我们能成"讲透

- 评委在 10/9 23:59 之后做的评审，**就是看 10/9 冻结的版本**——而我们冻结的是 v0.5.5（v0.5.6 commit 推到 origin 已是 10-12 凌晨，全量回归在 10-12 23:00 才跑完）。
- v0.5.6 的"事件历史回滚"和"取消后自动释放时间块"是答辩后 12 小时才实现的功能，**评委会完全没看到**。
- 也就是说，我们最强的工程化亮点（**七道闸 + 自动回滚 + 历史快照**）没有出现在评委会审的冻结包里。

#### E. 单人 solo 的成本

- 50 个脚本、14 道静态门禁、38 条闸用例、3 个对外文档、1 份发布说明、1 份交接文档——全部一个人写、一个人跑回归、一个人对资料库、一个人推代码。
- 答辩 3 分钟演示 + 2 分钟贡献说明环节，**solo 队伍天然吃亏**：演示里既要说应用，又要说贡献。评委在 5 分钟里看到的工程量，远不如有队友帮分担的多。

## 五、教训 / 经验（写入长期记忆）

1. **"在自己机器上能跑"不等于"在评委手里能跑"**。下次比赛，第一周就要把官方 rc.6 跑通，而不是第五周。
2. **新功能依赖外部服务时，本机测的只是降级路径**。`model.complete` / 邮件 / 第三方 API 都要么事先确认官方宿主支持，要么做成可选增强而不是核心卖点。
3. **没做上游 PR = 技术分 6/20**。哪怕是修文档、改一个拼写错误、提一个测试用例，**至少 1 个 PR** 是技术分保底。
4. **答辩冻结前的最后一周要专门用于"在官方宿主上完整跑一遍"**，而不是写新功能。v0.5.5 → v0.5.6 的所有改动，**评委一份都没看到**，等于白做。
5. **故事要单一**。"七道闸 + 自动回滚 + 历史快照"这个工程化闭环够做一个 demo；不要同时推"AI 排程"+"待办转日程"+"事件详情"+"OKR/周报"+"时间搜索"+"协作"——评委没时间逐个看。
6. **solo 队伍把工程量藏在数据里**。14 道静态门禁、38 条闸用例、3 个文档——这要写在 README 顶部，让评委扫一眼就知道这不是 MVP。
7. **对外动作（发版 / 合并 / 提 issue / 申请官方 host）必须由 ody-cai 执行**——这一条我们做对了，要继续守。
8. **比赛要"押对题"**。Ody 的 v0.5.6 评审意见是"只做 #4 + #5"——事后看，如果我们听话地**只做"七道闸 + 自动回滚" + 一个能跑通的小例子**，**可能创意分能拿满**。但我们贪多，把 Ody 没确认的 v0.5.5 全部继承下来了。
