## 一、新增功能

### 1. 事件版本历史与回滚

每次改期前，应用会自动保存该事件的当前版本快照到本地 `event-history.json`：

- 每个 UID 最多保留最近 5 个版本；
- 版本数据只存本机，不参与 ICS 导出；
- 在事件详情页新增「历史」标签页，可查看历次版本并按「回滚到 [N]」一键恢复；
- 回滚本身也会生成新版本，用户可以连续回滚。

这让「AI 给建议、用户做决定、还能回滚」成为完整闭环，直接回应 AI 改期的信任问题。

### 2. 取消日程后自动释放时间块

事件详情页新增「取消日程」按钮：

- 点击后事件 `STATUS` 改为 `CANCELLED`，并递增 `SEQUENCE` / 刷新 `DTSTAMP`；
- AI 排程或待办转日程产生的事件会被标记为 `auto`；
- 取消后，系统尝试把所有 `auto` 事件往更早的空档紧凑重排；
- 若找不到更早空档，或事件为全天/重复事件，则保持原位。

这是「agentic」闭环的体现：系统持续维护日历状态，而不仅仅是单次建议。

## 二、设计取舍与边界

- **不做搜索/统计/报告**：Ody 评审认为 #1–3 像功能补丁、稀释答辩主线，且统计/报告的自然语言查询容易露馅；v0.5.6 只保留评委故事最强的 #4 + #5。
- **不新增 capability / network.hosts**：纯本地功能，manifest 无需重新谈判白名单。
- **数据不出本机**：历史版本与 auto 事件标记均存旁路文件，不参与 ICS 导出。
- **ICS 往返无损**：取消事件导出时会带 `STATUS:CANCELLED`；所有改期仍走 `reschedule()` 唯一入口；预期 `run_conflict.sh` 仍保持「新增 0 / 改期 0 / 跳过 N」。
- **存储可控**：1000 事件 × 5 版本 × 约 0.5 KB ≈ 2.5 MB，远低于 16 MiB 存储上限。

## 三、已知限制

- `model` capability 在当前 card-host 环境仍报 unknown，AI 排程成功路径需等 ai-host 合入后才能真机验证；本版本降级路径（模型不可用时界面不卡死、不丢数据）已保留。
- manifest 已临时去签，最终 Release 需 Ody 用 OMA 私钥重新签名。
- 农历与调休数据仍只覆盖 2025–2026。
