## 一、新增功能

### 1. 对话式 AI 排程

在工具条新增「AI 排程」入口。用户可以用自然语言创建日程，例如：

> 下周三下午三点和张总开会，提前半小时提醒

应用会：
- 解析时间、参与人、重复规则、优先级；
- 自动检测与现有事件的冲突；
- 给出替代时段；
- 只有用户点击「确认写入」后，才通过 `reschedule()` 唯一入口写入事件库。

模型只参与建议，写入仍需用户确认，且新事件/改期仍经过形状、身份、日期、时段、日历、用户同意、复核七道校验。

### 2. 待办一键转日程

待办清单的每条可见待办右侧新增「排期」按钮。点击后：
- 按关键词估算时长（含「会/讨论/评审」→ 30 分钟，否则 60 分钟）；
- 在未来 7 天的 09:00–21:00 中自动挑选第一个空档；
- 生成对应日历事件，原待办保留（用户可手动删除）。

### 3. 事件详情页

点击事件进入详情抽屉，包含四个标签页：
- **笔记**：议程、想法等自由文本；
- **纪要**：会议纪要；
- **跟进**：可追加的多条后续跟进项；
- **链接**：附件/参考链接。

所有内容持久化到本地 `event-notes.json`，不随 ICS 导出，也不发网络请求。

### 4. OKR / 里程碑视图与手动周报

- 目标卡片支持设置期限（7 / 14 / 30 / 90 天）。
- 新增「生成本周周报」按钮：汇总本周事件、已完成待办与目标进度，生成一段纯文本周报。周报**仅复制/展示，不自动外发**（宿主无邮件自动发送能力）。

## 二、设计取舍与边界

- **不做自动邮件/邀请**：宿主未暴露可靠的发邮件 API，且自动外发属于越权行为；所有分享仍走用户手动复制/导出。
- **不做拖拽**：Splash 宿主无拖拽 API，待办转日程改为一键按钮。
- **模型输出不可信**：自然语言解析结果一律在界面上展示，用户确认后才写入；解析失败会给出明确原因。
- **数据不出本机**：事件详情笔记只存本地 storage，不参与 ICS 往返；ICS 导入/导出的无损标准维持「新增 0 / 改期 0 / 跳过 N」。

## 三、已知限制

- 农历与调休数据仍只覆盖 2025–2026。
- Windows 上天气与城市选择仍受宿主网络层限制（与 v0.5.2 相同，平台缺陷）。
- 自然语言日期解析依赖模型能力，复杂表达可能失败，失败时会回退到手动新建面板。
