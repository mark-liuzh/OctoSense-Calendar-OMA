# OctoSense 日历 v0.5.6 实施方案（Ody 审核版）

> 日期：2026-10-12 22:45  
> 基线分支：`v0.5.6`（已从 `origin/v0.5.5` 切出）  
> 目标：只实现用户在「下一版本」需求中**比赛内可落地**的子集，其余明确不做。

## 一、做哪些（复赛可落地）

| # | 功能 | 实现思路 | 依赖 |
|---|---|---|---|
| 1 | **本地时间搜索** | 在工具条新增「分析」按钮，打开分析面板切到「搜索」标签；输入关键词后遍历 `events` + `notes`，按 summary / location / description / organizer / 笔记文本匹配，返回命中事件列表（标题+日期）。 | 纯本地，不联网 |
| 2 | **本地统计查询** | 分析面板「统计」标签：提供预设按钮（本月会议数、本周会议数、加班事件数、平均每日会议时长）；同时支持简单的关键词查询（如「上个月我开了多少会」做本地模式匹配）。 | 纯本地，不联网 |
| 3 | **自动生成时间报告** | 分析面板「报告」标签：选择「本周/本月」，生成本地统计报告（事件总数、会议总时长、加班/周末事件数、最长连续空闲块）。 | 纯本地，不联网 |
| 4 | **事件版本历史与回滚** | 在事件详情抽屉增加「历史」标签；每次 `reschedule()` / `apply_ai_schedule()` / `todo_schedule()` / `save_new()` 前把当前事件快照写入 `event-history.json`（每个 uid 最多保留 5 个版本）；支持回滚到上一版本。 | 纯本地 storage |
| 5 | **会议取消后自动释放时间块** | 在事件详情页增加「取消事件」按钮，把事件 `status` 置为 `CANCELLED`；然后对所有 `auto-events.json` 里记录的自动排程事件调用 `rebalance_auto_events()`，把它们重新紧凑排布到最早空档（含刚释放的时段）。 | 纯本地，不联网 |

## 二、明确不做（越权/无权限/需后端）

- 专注时间保护 / 通知静音（宿主无通知/勿扰 API）
- 共享/团队/项目日历、预约页面、投票选时间、实时协作、公开日历 URL（无后端）
- 连接 Google/Outlook/Apple/Slack/Notion/Jira/GitHub/Zoom/飞书/钉钉/企业微信（域名/权限不在白名单）
- 邮件/Slack/Jira 自动建日程（越权，违反 PRIVACY 口径）
- Webhook/API/脚本可编程日历、插件市场、mini-app（无服务端/动态加载能力）

## 三、代码改动清单

### 3.1 新增状态与存储文件

在 `bundle/main.splash` 顶部状态区追加：

```splash
// v0.5.6 · 时间分析
let analyze_open = false
let analyze_tab = 0
let search_query = ""
let search_result = ""
let stats_query = ""
let stats_result = ""
let report_range = 0
let analyze_report_text = ""

// v0.5.6 · 事件历史 / 自动排程
let HISTORY_FILE = "event-history.json"
let history = {}
let AUTO_FILE = "auto-events.json"
let auto_uids = []
```

### 3.2 新增函数

| 函数 | 职责 |
|---|---|
| `load_history()` / `save_history()` | 读写 `event-history.json` |
| `load_auto()` / `save_auto()` | 读写 `auto-events.json` |
| `record_history(ev)` | 把事件快照压入 history[uid]，超限只保留最近 5 个 |
| `clone_event(e, status)` | 安全复制事件对象（用于取消/回滚时整体替换） |
| `toggle_analyze(tab)` / `close_analyze()` / `set_analyze_tab(i)` | 分析面板开关与标签切换 |
| `sync_analyze_panel()` | 同步分析面板文案/可见性 |
| `run_search()` | 执行本地搜索并生成结果文本 |
| `run_stats()` | 执行统计查询并生成结果文本 |
| `generate_time_report()` | 按本周/本月生成时间报告 |
| `cancel_event(uid)` | 把事件置为 CANCELLED，保存，触发 rebalance |
| `rebalance_auto_events()` | 遍历自动排程事件，把它们移到最早可用空档 |
| `find_earliest_slot(dur, skip_uid)` | 从当天起 14 天内找最早的 `dur` 分钟空档 |
| `rollback_event(uid)` | 从历史中弹出上一版本并写回事件库 |

### 3.3 修改现有函数

| 函数 | 修改 |
|---|---|
| `load()` | 调用 `load_history()` / `load_auto()` |
| `refresh_all()` | 调用 `sync_analyze_panel()` |
| `sync_panels()` | 把 `analyze_open` 纳入面板互斥；新增 `ui.analyze_panel.set_visible(...)` |
| `reschedule(uid, ...)` | 在替换事件对象前调用 `record_history(e)` |
| `apply_ai_schedule()` | 新建事件后把 uid 加入 `auto_uids` + `save_auto()` + `record_history(ev)` |
| `todo_schedule(k)` | 同上 |
| `save_new()` | 新建事件后调用 `record_history(ev)` |

### 3.4 UI 改动

- **工具条**：在「AI 排程」旁新增「分析」按钮（`ButtonFlat`），点击 `toggle_analyze(0)`。
- **分析面板**：在 `report_panel` 后新增 `analyze_panel`，内部三标签：
  - 搜索：输入框 + 「搜索」按钮 + 结果 Label。
  - 统计：输入框 + 「查询」按钮 + 快捷按钮行 + 结果 Label。
  - 报告：「本周/本月」切换按钮 + 「生成报告」按钮 + 结果 Label。
- **事件详情抽屉**：标签行增加「历史」按钮；新增历史页（版本数、上一版本摘要、回滚按钮）；标题行增加「取消事件」按钮。

## 四、数据边界与隐私

- 新增数据全部写本机 storage（`event-history.json`、`auto-events.json`），**不出设备**。
- 不读取系统日历、邮件、Slack、剪贴板历史。
- 不增加新的网络域名；`manifest.json` 的 `network.hosts` 保持不变。

## 六、风险与回退

| 风险 | 缓解 |
|---|---|
| 新增面板导致竖向预算超 892px | 分析面板与详情/周报同优先级互斥，且只在 `tab == 0` 显示；实现后实测 `/d` 布局树。 |
| 事件对象克隆漏字段导致导入/导出丢数据 | `clone_event()` 与 `new_event()` 字段表保持一致；导出前跑 ICS 往返自检。 |
| 历史文件膨胀挤占 16 MiB 存储 | 每个 uid 最多 5 个版本；只给手动/AI/待办事件记历史，导入事件不记。 |
| `auto-events.json` 里的事件被用户删除后残留 uid | rebalance 前先检查事件是否存在。 |
