## 一、为什么测这两条

初赛材料要求「至少一次可核对的操作结果 + 一个失败或空状态」。
本项目两个核心卖点是**多源 ICS 汇聚后的冲突消解**与**可带走的数据导出**，
而导出是否真的无损、冲突建议是否真的可执行，只有跑一遍才算数。

## 二、测试数据

| 文件 | 内容 |
| --- | --- |
| `seed.ics` | 3 个事件：黑客松初赛截止（10-04 10:00–11:00 UTC）、OMA 队伍同步会（10-05 14:30–16:00 Asia/Shanghai）、复赛版本冻结（10-09 全天，`VALUE=DATE`，`SEQUENCE:2`） |

设计意图：让两个事件的「承诺重量」不同，检验建议是否把**可动的一方**移走，
而不是随机挑一个。

- 黑客松初赛截止 → summary 含「截止」→ 权重 3（硬承诺）
- 复赛宣讲会 → 有 `ORGANIZER`，无硬关键词 → 权重 2（有约在前）

## 三、实测步骤与结果

复现命令：`bash tools/run_conflict.sh`（单进程内跑完全部步骤）

1. **干净启动** — 清空应用私有数据，保证每次结果可复现
2. **导入 `seed.ics`** — 空状态 → 面板 → 粘贴 → 解析 → 写入
   结果：`已写入 3 个事件 · 新增 3 / 改期 0 / 跳过 0`，无冲突
3. **再导入 `conflict.ics`** — 结果：`已写入 4 个事件 · 发现 1 处时间冲突`
4. **展开冲突详情** — 结果：
   `重叠 30 分钟 · 保留 黑客松初赛截止`
   `可动 · 复赛宣讲会（有约在前）`
   `移到当天 09:00-10:00 的空档`
5. **一键应用建议** — 结果：`已应用 1 条改期建议 · 剩余 0 处冲突`
   复赛宣讲会由 10:30–11:30 移到 09:00–10:00，与截止事件不再重叠
6. **导出 ICS** — 输入框得到 664 字节完整 ICS（4 个事件）
7. **往返幂等** — 把导出的 ICS **原样再解析一次**
   结果：`解析 4 个：新增 0 / 改期 0 / 跳过 4`
   → **这是「导出不丢信息」的硬证据**：类型参数完整，读回被识别为同一批事件
8. **回滚上一次导入** — 结果：`已回滚到 4 个事件`
9. **关于页** — 吉祥物、CC BY 4.0 署名、能力声明全部在视口内

**编译 / 运行错误数：0**

## 四、过程里发现并修掉的三个真实缺陷

这三个都不是「看起来不美」，而是会**静默毁坏数据**或**让功能不可达**：

1. **导出丢时区参数**
   `DTSTART;TZID=Asia/Shanghai:20261005T143000` 被输出成 `DTSTART:20261005T143000`
   —— 读回时变成「浮动时间」，时区语义丢失；全天事件的 `VALUE=DATE` 同样会退化成定时事件。
   修法：按 `all_day` / `timezone` 分支补回 `;VALUE=DATE` / `;TZID=`。

2. **改期丢 UTC 标记**
   一键改期后用 `date_of()` + `clock_compact()` 拼时间，把 `Z` 后缀吃掉了
   —— `20261004T103000Z` 变成 `20261004T090000`。
   修法：按 `start_utc` 补回后缀；同时**全天事件不再参与自动改期**
   （把整天承诺降级成 1 小时会议属于语义破坏），应用 0 条时给出明确提示。

3. **冲突一解决，「回滚」就消失了**
   冲突条原本只在 `冲突数 > 0` 时显示，应用建议后冲突归零 → 整条隐藏
   → 用户改错了无法撤销。
   修法：只要还有历史快照就保留该条（文案改为「无冲突 · 可回滚」）。

修 (3) 时踩了一次回归：冲突条改成常驻后多占约 52px，
把导入面板底部的「写入」按钮挤出 892px 视口（点不到）。最终条件为
`(有冲突 || 有快照) && !关于页打开 && !导入面板打开`。

## 五、已知限制

- **导入只支持粘贴**：宿主能力闭集里只申请了 `storage`，没有文件选择器、
  也没有剪贴板读取权限 —— 粘贴 `.ics` 文本是当前唯一可靠的导入通路。
- **无网络**：数据全部留在本机，不上传、不同步。
- **建议策略保守**：改期在当天 09:00–21:00 内按 15 分钟步进找第一个不冲突的空档，
  取「够用且最早」，不追求离原时间最近。
- 全天事件不参与自动改期。
