# 节假日标注与节日来源切换 · 实测记录

> 记录时间：2026-09-30 · 队伍 OMA · 应用 `com.oma.octosense.calendar 0.1.0`
> 复现命令：`bash tools/run_festival.sh`（退出码 0 = 全过）

---

## 1. 为什么要做

评审演示时被当场问到：「你作为一个日历，为什么不会显示国家的节假日？哪一天调休、哪一天不调休，全部没有标出来。」

这是硬伤 —— 中文用户看日历，第一眼找的就是放假和补班。于是补三件事：

1. **法定节假日要标出来**；
2. **调休上班日要区别于普通工作日**；
3. **节日来源要能切换**（只看中国 / 只看国际 / 都看），且**标出这一天是否放假**。

用户对第 3 点的原话定义得很具体：

> 正常上班的下面标注小黑点，放假就下面标个小绿点，调休就写一个「班」字。

这直接成了实现规格。

---

## 2. 最终标记语义

| 当天性质 | 日期文字 | 标记 | 颜色 |
| --- | --- | --- | --- |
| 法定放假 | 绿色加粗（`c_ok`） | **小绿点** | `#15803d` |
| 调休补班（本该休息的周末被调来上班） | 赤陶（`c_accent`） | **一个「班」字** | `#b4531f` |
| 有节日但**照常上班**（如万圣节、妇女节） | 常规墨色（`c_ink2`） | **深灰小黑点** | `#6b6560` |
| 有日程 | 不变 | 赤陶小点 | `#b4531f` |
| 普通日 | 次级墨色 | 无 | — |

三色三义，不靠位置猜。点与「班」字可以并存（比如某天既有日程又是补班日）。

月历下方两行说明：

- 第 1 行（绿点前缀）：**当月节日** —— 只有 1 个节日时带日期（`中秋 9/25`），多个时只列名字（`国庆 · 万圣节`）
- 第 2 行（赤陶点前缀）：**放假 / 调休安排** —— `放假 7 天 · 10/10 上班`；当月没有则整行让位

### 节日来源

按钮文案在 `节日 中国` → `节日 国际` → `节日 全部` 之间循环：

| 模式 | 中国节假日数据 | 国际固定节日 | 放假标记 |
| --- | --- | --- | --- |
| 仅中国 | 显示 | 不显示 | 显示 |
| 仅国际 | **不显示** | 显示 | **全部隐藏** |
| 全部 | 显示 | 显示 | 显示 |

「仅国际」时如果还留着国内放假的绿点和「班」字，等于切了个寂寞 —— 所以 `holiday_kind()` 在最前面就
`return 0`（见 `cn_holiday_shown()`）。

## 3. 数据来源与硬约束

- **必须内置。** 脚本应用只申请 `storage`，`hosts {}` 没有任何网络出口，
  所以节假日只能是随版本冻结的常量，不能联网拉取。
- **数据依据**：国务院办公厅《关于 2025 年部分节假日安排的通知》《关于 2026 年部分节假日安排的通知》。
- **范围**：2025、2026 两个年度。2027 年及以后**不会自动出现** —— 刻意取舍，
  宁可明确「没有数据」，也不要猜错让人误了上班。
- **国际节日只收固定日期的**（元旦 / 情人节 / 妇女节 / 愚人节 / 劳动节 / 儿童节 / 万圣节 / 平安夜 / 圣诞节）。
  复活节、感恩节这类浮动节日需要天文算法，本期不做。
- **国际节日不标放假。** 各国工作日规则不同，标错比不标更糟，只作「今天是这个节」的提示。

### 三个常量（`bundle/main.splash`）

```splash
let HOLIDAYS  = "|20250101|...|"   // 法定放假日（8 位日期），search("|YYYYMMDD|") 判命中
let WORKDAYS  = "|20250126|20250208|...|"   // 调休补班日
let CN_SPANS  = "20251001|20251008|国庆中秋|..."   // 日期区间 → 节日名，步长 3
let INTL_FIXED = "0101|元旦|0214|情人节|..."        // MMDD → 节日名，步长 2
```

**竖线写法有讲究**：每行首尾都写竖线会让拼接后出现 `||` 空字段，`split("|")` 的步长
会从 3 变成 4 —— 这个坑真的踩了，当时表现为「节日名称永远为空」。

## 4. 本轮修掉的四个缺陷

### ① 全项目所有「用 View 画背景」的地方，一个像素都没画

makepad 里 `View = ViewBase {}`，**既没有 `show_bg: true`，也没有带 `pixel` 的 `draw_bg`**。
所以下面这种写法只是往一个永远不绘制的 shader 上写了个颜色：

```splash
View{ draw_bg +: {color: c_ok} }     // 不报错、布局树里也有尺寸 —— 但什么都不画
```

此前没被发现，是因为这个设计几乎单色（大量 `c_card` / `c_paper` 白底画在白纸上，画不出来也看不出来）。
一旦要画绿点、黑点、色条，就全露馅了。

**受损元素**：今天格的实心墨底、日历格的事件点 / 放假绿点 / 小黑点、说明行的图例点、
状态条项目符号、空状态的 36px 空心圆环、事件卡片左侧色条、冲突条与预览条的有色底与描边。

**修法**：`tools/paintfix.py` 结构感知批量替换（50 处 `View` → `RoundedView`；
6 处小方块 → `CircleView` 且 `border_radius` 归 0）。规则写进源码顶部注释，并作为门禁跑。

> `CircleView` 的 `border_radius` **必须归 0**：`radius <= 0` 才会自动取 `min(w,h)/2`；
> 写 2.0 / 2.5 会让半径 ≥ 半边长，圆角矩形直接退化消失（换成能画的控件也还是看不见）。

**验证**：截图回读像素。修复前 `.runtime/oct-all.png` 全图**零个绿色像素**，
三个标记点全部采到 `#ffffff`；修复后精确命中 `#15803d`（放假绿）/ `#6b6560`（照常上班灰）。

### ② 「班」字只画出 2 个像素

现象：调休日的标记看着像个小点，放大 14 倍才看出是「班」字中间那几条横。

根因不是「没画」，而是**被挤扁**：

`Label{height: 19}` 放进 `flow: Down` 时，makepad 取 **`max(显式高度, 自然行盒)`**。
`font_size: 12` 的文字自然行盒**约 26 px** —— 写 19 / 21 / 23 都照样占 26。
于是「单元格 34 = 数字 19 + 标记行 13」的账算错了，标记行实得只有 8~13 px，
「班」字上下被裁，只剩中间几条横。

实测三档：

| 单元格高度 | 标记行实得高度 | 结果 |
| --- | --- | --- |
| 34 px | 8~13 px | 「班」= 2 px 残片 |
| 46 px | 17 px | 仍是残片 |
| **52 px** | **23 px** | **「班」完整清晰** |

**修法**：单元格 34 → 52，网格高度 `6 × 52 + 5 × 2 = 322`；数字行 / 标记行各 23；
标记行的 `align` 用 `Align{x: 0.5 y: 0.5}`（`y: 0.0` 也会裁字）。

> 定位方法值得记一笔：`/snap` 快照里标记行报的是 **13** 而不是源码写的 19，
> 顺着这个数字差才找到「自然行盒吃掉 26px」这件事。
> **排查布局问题要看兄弟节点的实测高度，不要看自己写了多少。**

### ③ 翻月时大标题与卡片月份标签不刷新

静态 `Label` 的 `text:` 属性**只在建树时求值一次**。翻到 10 月后页头还写着 9 月。

**修法**：立 id（`month_title :=` / `cal_ym :=`）+ 在 `refresh_all()` 里 `set_text()`。

### ④ 节日说明行折行被裁

「全部」模式下「国庆 10/1 · 万圣节 10/31 · 放假 7 天 · 10/10 上班」约 452 px，
超过了 359 px 的可用宽度，固定 42 px 高的容器把第二行的「班」字裁掉。

**修法**：拆成静态两行（`fest_line` / `fest_row2 + fest_line2`，用 `set_visible` 让位），
并让多节日时只列名字（最坏约 209 px）。

## 5. 实测覆盖

`bash tools/run_festival.sh` —— 9 步，**读布局树 + 回读截图像素**双通道断言。

`/snap` 快照只有 `i / ty / r / w`，**不带颜色**，所以「绿点 / 黑点 / 赤陶字」必须回读像素才能验证。
判定器是 `tools/e2e.py` 的 `dot_kinds()`：在标记点中心取 5×5 邻域，**按像素投票**定性。

> 为什么不能取中心像素或「最深像素」：3.5 px 的圆点在当前 DPI 下只有约 6 px，
> 边缘一圈全是抗锯齿过渡色；而放假绿 `#15803d` 与照常上班灰 `#6b6560` 的**亮度几乎相同**
> （≈100 / ≈102），两种取法都判不准。

## 6. 已知限制（如实说明）

- 只内置 **2025 / 2026**；2027 年及以后不显示节假日数据。
- 国际节日只收**固定日期**的；复活节、感恩节等浮动节日不收录。
- 国际节日**不标放假**（各国外汇 / 工作日规则不同）。
- 节日来源模式**不落盘**，重启回到「中国」——单次会话内的偏好，不引入额外状态。
- 「班」字是小字（`font_size: 11`），在高 DPI 下清晰，在低分屏上会偏小；
  这是日历格子宽度（约 51 px）与 7 列布局共同决定的。

## 7. 过程中修掉的测试自身缺陷

- **测试环境竞态（两层）**。
  第一层：上一轮宿主的存储目录在 Windows 上未及时释放，`rm -rf app-data` 静默失败，
  下一轮带着 6 个残留事件开跑 → 日历里凭空多出日程点，而布局树断言全过
  （事件是异步 `load()` 进来的），只有像素断言对不上，报错完全指不到真因。
  第一版修法是 `kill_host()` 等进程真正退出 + `boot_host()` 清完目录后校验为空（重试 5 次）—— 治标。
  第二层（真正的根因）：`run_festival.sh` **末尾漏了 `kill_host`**，跑完把宿主留在后台。
  危害不落在自己身上，而落在**下一条流程**：僵尸宿主占着端口与存储目录，
  新宿主绑不上端口，而就绪探测却打到了僵尸身上 —— 那一条流程其实全程在测别人的进程。
  最终修法三条：
  1. `run_festival.sh` 补上收工；
  2. `kill_host()` 改成「杀 → 轮询确认消失 → 最多 3 轮」，失败时打印 PID 清单；
  3. `boot_host()` **不再原地清空存储**，改为**每轮换一个全新的
     `app-data-<时间戳>-<pid>` 目录**，旧的尽力删。删不掉也不影响本轮，
     整条「能否删掉上一轮目录」的依赖就此消除；并在起宿主前先确认端口是空的，
     把「探测打到旧宿主」这条路直接堵死。
- **取色不稳**：`dotcolor` 最初取 3×3 中位色，抗锯齿边缘会取到 `#88be9c` 这类浅绿，无法断言。改为投票法。
- **像素量尺自身有缺陷**：局部放大工具原先按逻辑坐标抽点再复制，逻辑区 100 px 在 1.75 缩放下
  其实是 175 个实际像素，压成 100 列会漏掉笔画（数字、小圆点整条消失，看起来像「整块白」或「瓦片重复」）。
  改成先算逻辑区对应的实际像素矩形，再逐实际像素输出放大块。
- **测试自己的断言写错**：第一版在 10 月里找 9/28 的补班日，拆成 2025-10 与 2025-09 两步后修正。

「画背景必须用可绘制控件」规则）：

（唯一警告为「未签名」，需由人用密钥签名，与代码无关）。

### 为什么把回归固化成 run_all.sh

这五条流程共用同一个宿主进程与远程控制端口，串行跑法的正确性完全押在
「每条流程结束时宿主真的退了」上。一旦某条漏了收工，**失败会出现在下一条**
（端口被占 / 存储清不掉），报错信息与真正的原因隔了一层 —— 本项目就因此误伤过一次。

`run_all.sh` 因此显式做三件事：每条开跑前确认端口是空的；每条结束后兜底
`kill_host` 并校验端口已释放；每条使用全新的存储目录。这三条把「漏收工」
从一个**静默的、跨脚本的**故障，变成了**当场可见**的故障。
